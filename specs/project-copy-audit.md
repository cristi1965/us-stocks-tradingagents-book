# 全工程文字检查约定

用户要求：全工程按 ELI5 方式检查，不能只改新版28课。

## 范围
清点项目自有文本文件，包含旧版页面、全部课程层、专题导读、模拟器、Python工具、CSS生成文案、项目配置说明和Markdown文档。
依赖代码、图片二进制、缓存、截图、自动生成的历史证据不当作课程文案改写。
前轮只扫描的118篇，本轮按用户要求逐篇阅读并写成通俗讲解，默认展示改写版；原文单独保留。每篇记录改写范围和删改原因，不能用标题替换冒充全文改写。

## 修改原则
先解释事情，再引入术语；一段只讲一件事；反馈指出错在哪里，不用人物台词覆盖。
程序字段、函数名、测试标识不翻译。数值与公式保持一致；不制造审核通过、实时数据或收益保证。
历史研究与审查记录保留原日期和结论，加白话阅读说明，不伪造新的审查结果。

## 任务
1. 文件清单及文字来源分类。
2. 旧体验层、课程与专题导读、工具三个区域独立审读修改。
3. 主线程检查HTML、CSS文字、当前课程、元信息与文档。
4. 语法检查、新版回归、旧版逐章浏览检查及关键反馈验证。
5. 生成逐文件覆盖表，区分精读、扫描、历史记录和排除项，列明剩余限制。
